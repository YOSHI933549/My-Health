# YOSHI Health Tracker

①健康 ②筋肉トレーニング ③体重を上げる ― この3つを目標に、食事・トレーニング・体重を一元管理する
ブラウザ完結型の記録アプリです。サーバーやビルド不要、`index.html` を開くだけで使えます。

## 使い方

1. `index.html` をブラウザで開く(ホーム画面への追加方法は下記「スマホにインストール」を参照)
2. 「設定」タブで身長・年齢・性別・活動レベル・増量目標を入力して保存
3. 「体重」タブで今日の体重を記録(初回は必須。以後は毎日〜数日おきに記録)
4. 「食事」タブで食べたものを記録(写真は記録用として添付可能、栄養は手入力)
5. 「筋トレ」タブで種目(胸/背中/脚/肩/腕/体幹の基礎種目から選択、リストにない種目は
   「＋ その他(自由入力)」から入力可能)を記録(回数・重量は入力せず、やった種目だけ記録)
6. 「今日」タブでカロリー・たんぱく質・脂質・炭水化物の目標に対する達成率を確認
7. 「分析」タブで、選んだ期間(1週間/1ヶ月/3ヶ月/全期間)の平均達成率・体重の増減ペース・
   トレーニング頻度と、そこから導いた「気づき」「専門家アドバイス」を確認

## 目標値の計算方法

- 基礎代謝(BMR): Mifflin-St Jeor式
- 消費カロリー(TDEE) = BMR × 活動レベル係数
- 摂取目標カロリー = TDEE + 増量分の上乗せカロリー(設定タブで調整、デフォルト +400kcal)
- **たんぱく質目標 = 体重(kg) × 2g**(指定どおり)
- 脂質目標 = 摂取目標カロリー × 設定した割合(デフォルト25%) ÷ 9
- 炭水化物目標 = 残りのカロリーから算出

体重を記録するたびに基準体重が更新され、目標値も自動的に再計算されます。

## 分析タブ(ルールベース分析)

外部AIやサーバーを使わず、記録データから機械的に集計・判定して「気づき」「専門家アドバイス」を表示します。

- 平均カロリー/たんぱく質/脂質/炭水化物達成率: 選んだ期間内で食事を記録した日について、
  その日時点の体重をもとに計算した目標(BMR→TDEE→摂取目標カロリー、たんぱく質=体重×2g、
  脂質・炭水化物は設定タブの配分)と実際の摂取量を比較した平均
- 体重ペース: 期間内で最初と最後の体重記録の差を、週あたりに換算(2件未満なら「記録不足」)
- トレーニング日数: 期間内でトレーニングを1件でも記録した日数
- 気づきコメント: 上記の数値をしきい値判定して自動生成(例: カロリー90%未満→不足を指摘、
  体重ペース週+0.1〜0.5kg→良いペースと評価、など)
- 専門家アドバイス: 「気づき」よりもう一段具体的な対策を、複数の角度から提案
  - **栄養バランス**: 不足している栄養素について、区分(朝食/昼食/夕食/間食)ごとの平均量・
    平均時刻を比較し、最も少ない区分と、その時間帯に足しやすい食品を提案。脂質の摂りすぎや
    PFC配分のずれも指摘
  - **栄養面(何を食べているか)**: メニュー名から食品の種類を判定し、野菜・魚・果物の登場頻度、
    たんぱく源の種類の偏り、プロテイン(粉)への依存度、メニューの単調さを指摘。カロリーとPFCが
    合っていても不足しやすい、ビタミン・ミネラル・食物繊維の観点を補う
  - **食べ方・タイミング**: 朝食の欠食率、たんぱく質が1食に偏っていないか、1日の食事回数、
    最後の食事の時刻、間食が占めるカロリーの割合
  - **生活リズム**: 平日と週末のカロリー達成率の差、トレーニングした日/しない日の摂取量の差
  - **トレーニング**: 記録のない部位、特定部位への偏り、最後のトレーニングからの日数
  - **体重の動き**: カロリーは足りているのに体重が動かない場合の上乗せ提案、たんぱく質不足の
    まま増えている場合の指摘、体重記録の頻度
  - 候補を優先度順に並べ、同じ分野に偏らないよう分野ごとの上限をかけて最大7件まで表示します
  - いずれも外部AIは使わず、記録の集計だけで生成しています

## データの保存場所

すべてのデータ(プロフィール・食事記録・トレーニング記録・体重記録・写真)は、
このアプリを開いているブラウザの `localStorage` にのみ保存されます。
外部サーバーへの送信は一切行いません。

- 機種変更・ブラウザ変更の前には「設定」タブの **JSONをエクスポート** で必ずバックアップしてください
- 別の端末やブラウザで使う場合は、エクスポートしたJSONを **JSONをインポート** で読み込んでください、
  または下記の「他の端末と同期」を設定すると自動化できます
- ブラウザのキャッシュ削除・シークレットモードではデータが失われるので注意してください

## 他の端末と同期(Google Drive、任意)

PC・iPhoneなど複数の端末で同じ記録を使いたい場合、Googleアカウントでログインすると
Google Driveの「アプリ専用フォルダ」(このアプリからしか読み書きできない、あなたの
Drive上の他のファイルからは独立した領域)経由で自動同期できます。設定しなくても
アプリ自体は今まで通り使えます。

### セットアップ(最初に1回だけ・所要5分程度)

1. https://console.cloud.google.com/ にアクセスし、新しいプロジェクトを作成
   (例:「YOSHI Health Tracker」)
2. 左メニュー「APIとサービス」→「ライブラリ」で **Google Drive API** を検索して有効化
3. 「APIとサービス」→「OAuth同意画面」
   - User Type: **外部(External)**
   - アプリ名: 任意(例:「健康トラッカー」)、サポートメール: 自分のGmailアドレス
   - 「テストユーザー」に自分のGmailアドレスを追加(これで審査不要のまま自分だけ使えます)
4. 「APIとサービス」→「認証情報」→「+ 認証情報を作成」→「OAuthクライアントID」
   - アプリケーションの種類: **ウェブアプリケーション**
   - 「承認済みのJavaScript生成元」に `https://yoshi933549.github.io` を追加
   - 作成後に表示される **クライアントID**(`xxxxx.apps.googleusercontent.com` の形式)をコピー
5. `js/sync.js` の先頭にある `GOOGLE_CLIENT_ID` を、コピーしたクライアントIDに置き換えて保存・デプロイ

設定が完了すると、「設定」タブの「他の端末と同期」に「Googleでログインして同期」ボタンが
表示されます。ログインすると、記録するたびに自動でGoogle Driveへ保存され、他の端末で
開いたときに新しい方(タイムスタンプ比較)が自動的に反映されます。

### 制限事項

- 複雑な自動マージは行わず、「最後に保存した方が勝つ」単純な方式です。2台で同時に別々の
  記録を追加した場合、後から同期した方の内容で上書きされます(通常の使い方では起きにくい想定です)
- iPhoneのSafariはプライバシー保護機能により、ログインしたままでも自動更新が効かないことが
  あります。その場合は「設定」タブの「今すぐ同期」を1回タップしてください
- クライアントIDは公開情報として扱われます(client secretではないので、コードに直接
  書いても問題ありません)が、OAuth同意画面を「本番公開」しない限り、テストユーザーに
  登録したアカウント以外はログインできません

## 体重計との自動連携(iPhone ヘルスケア → n8n、任意)

Apple Healthに同期する体重計(RENPHO・Withings・Eufyなど)を使っている場合、
n8n経由でこのアプリに体重を自動的に取り込めます。

### 仕組み

1. 体重計のメーカーアプリがBluetoothで測定値を受信し、Apple Healthに記録
2. iPhoneの「ショートカット」で、ヘルスケアの最新の体重を取り出してn8nのWebhookに
   送信するショートカットを1つ作成(手動実行でも、オートメーションからの自動実行でもOK)
3. n8n(`YOSHI 体重同期` ワークフロー、Data Table `yoshi_weight_log` に保存)が受け取って保存
4. このアプリが別のWebhook(GET)を定期的に取得し、まだ記録されていない日付だけを
   体重ログに追加(「隙間埋め」方式。アプリ内で手入力・編集した記録は上書きしません)

n8n側のWebhook URLには秘密のトークンが含まれるため、**リポジトリのコードには一切含めず**、
「設定」タブの「体重計と自動連携」欄にご自身で貼り付けてブラウザ内(localStorage)にのみ
保存する設計です。

### セットアップ

1. 「設定」タブの「体重計と自動連携」に、n8nから発行された**取得用URL**(GET、
   `.../webhook/yoshi-weight-out?token=...`)を貼り付けて保存
2. iPhone側でヘルスケアのデータをn8nに送る仕組みを用意する(下記いずれか)

投稿用URL・取得用URL・トークンは、このアプリの管理者(n8nワークフローの所有者)が発行します。

#### 方法A: ショートカットで送る(検証済み・おすすめ)

iPhone標準の「ショートカット」アプリで、**3つのアクションだけ**の構成にできます。
日付の計算もJSONの組み立てもn8n側で処理するため、POSTや本文の設定は不要です。
n8n側は `.../webhook/yoshi-weight-simple?token=...&weight=...` というGETリクエストを
受け取り、日付は受信時の日本時間の日付を自動で使います。

1. 「ショートカット」アプリで新規ショートカットを作成
2. **ヘルスケアサンプルを検索** を追加
   - 種類: **体重(Weight)**
   - 開始日のフィルタ: **「過去の期間内 10000日」** など、全期間が対象になる条件にする
     (フィルタの値が空のままだと検索結果が0件になり、体重が送信されません)
   - 単位: kg / 並び順序: 開始日 / 順序: 新しい順 / 制限: オン・1項目
3. **ヘルスケアサンプルの詳細を取得** を追加 → 詳細の項目を **「値」** にする
   (iOSのバージョンによっては「数量」ではなく「値」と表示されます)
4. **URLの内容を取得** を追加 → URL欄に
   `https://<n8nのホスト>/webhook/yoshi-weight-simple?token=<トークン>&weight=`
   を貼り付け、**末尾に手順3の「値」を変数として挿入**する

**貼り付け時の注意**: チャットやWebからURLをコピーすると装飾付き(リッチテキスト)として
貼り付けられ、「リッチテキストをURLに変換できなかった」というエラーになることがあります。
その場合はSafariのアドレス欄に一度貼り付けてからコピーし直すと、装飾なしの文字列になります。

自動実行したい場合は、オートメーション(例: 体重計のメーカーアプリを開いたとき)から
「ショートカットを実行」でこのショートカットを呼び出し、「実行前に確認」をオフにします。

#### 方法B: Health Auto Export アプリを使う

[Health Auto Export](https://apps.apple.com/app/id1115567069) アプリのREST API連携でも
送信できる想定で、n8n側は対応済みです(このアプリはPOST本文を自由に編集できないため、
認証は**カスタムヘッダー** `x-yoshi-token` で行い、アプリ独自のJSON構造から体重の項目を
n8n側が自動的に探して取り込みます)。

1. アプリ内で「体重」(Weight/Body Mass)へのアクセスを許可
2. 「Automations」→ 新規作成 → REST API
3. URL: **投稿用URL**(POST、`.../webhook/yoshi-weight-in`)
4. 「ヘッダーを追加」で `x-yoshi-token` = (トークン)を追加
5. データタイプ: ヘルス指標 → 健康メトリックを選択で**体重のみ**を選ぶ
6. エクスポート形式: JSON のまま保存し、トリガーを設定

ただし実際に試したところ、アプリ側で「エクスポートは正常に完了しませんでした」という
エラーになり、n8nまでリクエストが届きませんでした(Safariから同じホストへは到達できる状態
でも発生)。原因はアプリ側にあると思われるため、確実に動く方法Aを推奨します。

#### 方法C: ショートカットからJSONをPOSTする(従来方式)

- 「ヘルスケアのサンプルを検索」→ 種類: 体重、並べ替え: 新しい順、上限: 1件
- 「URLの内容を取得」→ **投稿用URL**(POST、`.../webhook/yoshi-weight-in`)に、
  JSON本文 `{"date": "<今日の日付>", "weight": <取得した体重>, "token": "<秘密のトークン>"}` を送信

アクション数は増えますが、n8n側は引き続きこの形式も受け付けます。

### なるべく早く反映させたい場合

- アプリ側は、設定タブでURLを保存すると**表示中は20秒おきに自動取得**します(タブが
  バックグラウンドの間は止まります)。n8nに届いていればアプリを開いた瞬間にほぼ反映されます
- iPhone側は「Appを開いたとき」トリガーが体感的に一番速いです(体重計に乗った直後に
  メーカーアプリを開く操作と同時に発火するため)
- さらに即座に反映させたい場合は、iPhoneの「バックタップ」(設定→アクセシビリティ→
  タッチ→背面タップ)に同じショートカットを割り当てておくと、体重計に乗った直後に
  iPhoneの背面を2回叩くだけで手動起動できます(オートメーションと併用可能)

## 調べた食事の栄養を自動で取り込む(任意)

外食やコンビニ食品など、栄養成分を調べてもらった食事を、**手入力せずに**アプリの食事
記録へ自動で追加できます。体重の自動連携と同じ n8n の仕組みを使っています。

流れ:

1. 調べた食事の内容(日付・時間・区分・メニュー名・カロリー・たんぱく質・脂質・炭水化物)を
   n8nのData Table `yoshi_meal_inbox` に1行書き込む
2. アプリが**表示中は20秒おきに**取得用URLを見に行き、新しい行を食事記録へ追加する
3. 「設定」タブの「今すぐ取得」を押せば、その場ですぐ取り込むこともできる

### セットアップ

「設定」タブの「調べた食事を自動で取り込む」にある**食事の取得用URL**(GET、トークン付き)
を貼り付けて「保存」を押すだけです。URLはブラウザのローカル保存領域にのみ保持され、
リポジトリのコードには一切含めません。

### 調べて記録する作業自体の自動化(record-meal スキル)

`.claude/skills/record-meal/` に、この一連の作業(栄養成分を調べる → 数値を検算する →
受け取り箱に書き込む → 確認する)をまとめたスキルを置いています。

「松屋の牛めし大盛を反映して」のように食べたものを伝えるだけで、Claudeがこの手順を
たどって記録まで済ませます。スキルには、サイズ違いの数値を拾い間違えないための
検算のしかたや、日付をJSTで取ること、報告に栄養アドバイスを付けないことなどを
書いてあります。

### 二重取り込み・復活の防止

取り込んだ行のIDは `importedMealIds` として端末内に記録されます。そのため、

- 同じ行が何度も追加されることはありません
- 取り込んだ記録をアプリ側で削除しても、次の取得で復活することはありません

## 写真について

食事の写真(「写真(記録用・任意)」欄)はその場でブラウザ内で自動リサイズ(最大480px・
JPEG圧縮)してから保存されるため、記録・見返し用の添付画像としてのみ利用します。

一方、「栄養成分表示の写真から自動入力」欄はプロテインやコンビニ食品などのパッケージに
印字された栄養成分表(エネルギー・たんぱく質・脂質・炭水化物)を撮影すると、OCR
(Tesseract.js、初回利用時のみCDNから読み込み)でブラウザ内だけの処理として数値を
読み取り、カロリー・PFC欄に自動入力します。この写真自体は解析にのみ使い、保存はしません。
OCRなので誤読の可能性があります。読み取り後は必ず数値を確認・修正してから記録してください。

## スマホにインストール(ホーム画面に追加)

このアプリは PWA(manifest + Service Worker)対応にしてあるので、ホーム画面に追加すると
アイコンタップで直接開ける・オフラインでも動く・ブラウザのアドレスバーが出ない、という
ネイティブアプリに近い見た目で使えます。

### 1. まず公開URLを用意する(初回のみ・手動設定が必要)

GitHub Pages で公開するための Actions ワークフロー(`.github/workflows/deploy-pages.yml`)は
リポジトリに含めていますが、**Pages の公開設定自体はGitHubの管理画面上でしか行えない**ため、
以下だけは手動でお願いします。

1. GitHubでこのリポジトリの **Settings → Pages** を開く
2. 「Build and deployment」の **Source** を **GitHub Actions** に変更
3. このブランチを `main` にマージ(またはmainにpush)すると、Actionsが自動でデプロイします
4. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` でアクセスできるようになります
   (Actionsタブのデプロイログ、またはPages設定画面にURLが表示されます)

### 2. スマホのブラウザでURLを開き、ホーム画面に追加する

**iPhone(Safari)**
1. 公開URLをSafariで開く
2. 下部の共有ボタン(□に↑)をタップ
3. 「ホーム画面に追加」を選択 → 追加

**Android(Chrome)**
1. 公開URLをChromeで開く
2. 右上の「⋮」メニュー、または自動で出る「アプリをインストール」バナーをタップ
3. 「インストール」または「ホーム画面に追加」を選択

追加後はアイコンをタップするだけで、緑のヘッダーとタブバーだけのアプリ画面が
フルスクリーンで開きます。データは引き続きそのブラウザの `localStorage` に保存されるため、
Safari版とChrome版など、開くブラウザ・端末が変わるとデータも別になります(バックアップは
「設定」タブのJSONエクスポート/インポートを使ってください)。

```
index.html      画面構成(ダッシュボード/食事/筋トレ/体重/設定の5タブ)
css/style.css   スタイル(ライト/ダークモード自動対応)
js/app.js       ロジック(データ保存・目標計算・グラフ描画など、外部依存なし)
js/sync.js      Google Drive経由の端末間同期(任意機能、要セットアップ)
js/n8n-sync.js  n8n経由の体重・食事の自動取り込み(任意機能、要セットアップ)
manifest.json   PWAマニフェスト(アプリ名・アイコン・スタンドアロン表示設定)
sw.js           Service Worker(アプリ本体をオフラインキャッシュ)
icons/          ホーム画面アイコン(192/512/Apple touch icon/favicon)
.github/workflows/deploy-pages.yml  GitHub Pagesへの自動デプロイ
docs/           別プロジェクト(SNS/YouTube自動収集のn8nワークフロー)のドキュメント
```

外部ライブラリやビルドツールには依存していないため、オフラインでもそのまま動作します。
